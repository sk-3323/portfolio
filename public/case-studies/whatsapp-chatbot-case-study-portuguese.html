The Challenge

A busy clinic drowning
in WhatsApp messages

Dr. Weidson's three-city practice receives hundreds of WhatsApp inquiries daily. Scheduling, payment collection, and follow-up were entirely manual — creating bottlenecks, lost bookings, and late-night receptionist stress.

⏰

After-hours blackout

Patients messaging outside business hours received no reply, losing potential appointments to competitors available instantly online.

💸

Manual payment chasing

Billing via Asaas required staff to manually create charges, send links, and confirm payments — each booking took 10–15 minutes of admin time.

🔄

Zero follow-up system

Patients who inquired but didn't book were simply forgotten. No re-engagement, no reminders, no recovery of warm leads.

🏥

Multi-city complexity

Three locations — Barreiros, Recife, Palmares — each with different availability and service configurations, too complex for a simple FAQ bot.

🧠

Context blindness

Staff had no unified patient history. Repeat callers had to re-explain their needs every time, degrading the care experience.

🛑

Human interruptions

When a human agent took over a conversation, the bot needed to pause intelligently — then resume without replaying past context.

Technology Stack

Built with best-in-class
open infrastructure

Every component chosen for reliability, composability, and zero vendor lock-in.

n8n
Self-hosted workflow automation. All four workflows run here, with sub-workflow calls and custom JavaScript nodes.

Evolution API
WhatsApp Business API gateway. Handles incoming webhooks and outbound message delivery with full message type support.

OpenAI GPT-4o
The AI agent brain. Equipped with 8 tools: booking, calendar, patient lookup, human escalation, follow-up queue, and more.
🗄️
Supabase
PostgreSQL-backed database storing patients, consultations, and the follow-up queue. Used as the system of record.
⚡
Redis
In-memory store for the human-intervention block mechanism. TTL-based keys pause the AI when a human agent is active.
📌
Pinecone
Vector database for knowledge-base retrieval. Embeds clinic documents so the AI can answer FAQ questions with accuracy.
💰
Asaas
Brazilian payment gateway. Handles PIX, credit card, and boleto charges. Fires webhooks on payment confirmation.
📅
Google Calendar
Appointment scheduling and availability checking. The AI queries free slots before confirming any booking.

Real conversation flows the AI handles end-to-end, without any human intervention.

New patient booking

A new patient contacts the clinic via WhatsApp. The AI identifies them as a new contact, collects their consultation type and city preference, queries Google Calendar for availability, and books the appointment — generating a payment link in one smooth conversation.

Payment confirmation

When a patient completes their PIX payment, Asaas fires a webhook that triggers the payment confirmation workflow. The patient's consultation status updates instantly and they receive a personalized confirmation message — with no staff involvement.

✓Asaas webhook received and validated instantly
✓Consultation marked as paid in Supabase
✓Pending follow-ups cancelled automatically
✓Confirmation WhatsApp sent with appointment details

Automated follow-up

A patient inquired but didn't complete their booking. The follow-up queue engine sends gentle re-engagement messages at 1 hour, 6 hours, and 2 days after their last interaction — recovering warm leads passively, around the clock.

✓Step 0: reminder 1 hour after last contact
✓Step 1: second touch 6 hours after last contact
✓Step 2: final re-engagement after 2 days
✓All steps cancelled instantly if patient books or pays
✓Runs entirely on a cron schedule — zero manual effort

Human agent handoff

When a human receptionist needs to step into a conversation, they send "/delete" and the AI pauses silently. A Redis key with a configurable TTL (default 10 min) blocks the AI from responding. Once TTL expires, the AI resumes naturally without replaying context.

✓Human types /delete → AI paused immediately via Redis
✓No AI responses during human intervention window
✓Configurable pause duration (seconds, set in n8n)
✓AI resumes automatically when TTL expires
✓Full conversation memory preserved across handoff

Under the Hood

Key engineering
decisions

The details that make it production-grade, not just a proof of concept.

Redis · TTL-based locking
Human-intervention block
When a human agent replies from the clinic side, "fromMe: true" triggers a Redis key set with a 600-second TTL. The AI checks this key on every incoming message and silences itself until it expires.
n8n Wait node · Loop
Natural reply pacing
AI responses are split into individual sentences, then iterated with a Wait node between each. This prevents a wall of text and makes the bot feel more like a real person typing in real-time.
Pinecone · OpenAI embeddings
Knowledge base retrieval
Clinic documents (pricing, location, policies) are chunked, embedded with OpenAI, and stored in Pinecone. The AI retrieves relevant context for each query using vector similarity search.
JavaScript Code node
Input normalization
All city names, consultation types, and billing types go through a custom JS normalization step — stripping accents, uppercasing, and mapping Portuguese variants — before any external API call. Validation errors return structured error messages.
Supabase · follow_up_queue table
Stateful follow-up engine
Each patient inquiry creates a queue row with step=0 and last_message_at. A cron workflow filters rows whose timing conditions are met (1h / 6h / 2d), sends the message, advances the step, and cancels the sequence on payment.
n8n sub-workflow
Modular tool architecture
Each AI capability (book appointment, check availability, human review, cancel booking, reschedule) is a separate n8n sub-workflow exposed as an AI tool. This keeps the main agent lean and each tool independently testable.
